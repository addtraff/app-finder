## 1. Цель

Отчёт отвечает на вопрос: **в какую нишу и с каким образцом зайти на органическом трафике (ASO) и, по возможности, условно-бесплатном (УБТ), без закупки.**

Отличие от v1.0 — по методике v2.0 решение больше не сводится к одному числу. Ниша описывается четырьмя величинами, приложение — семью проверками:

| Вопрос | Уровень | Чем отвечается |
|---|---|---|
| Есть ли куда встать | Ниша | **Свобода** — процентиль 0–100 |
| Даст ли это место трафик | Ниша | **Ёмкость** — установок в месяц с интервалом |
| Не выкуплен ли этот трафик | Ниша | **Чистота** — доля спроса без закупки в топ-10 |
| Как быстро | Ниша | **Срок** — месяцев до входа в топ-10 |
| Годится ли образец | Приложение | Семь проверок: шесть методики v1.1 и 3b «трафик поисковый» |
| Не убьёт ли очевидное | Приложение | Дисквалификаторы |

Композитные скоры существуют только как ключи сортировки. Принципы сохраняются: инструмент измеряет, не решает; скор ранжирует, а не предсказывает; пусто — не ноль; пороги — квантили; непроверенное не считается пройденным; у отрицательной улики есть дата.

### 1.1. Сценарий

1. Аналитик открывает «Топ ниш» в режиме «Ворлдвайд», смотрит квадрант «Цель» матрицы решения: свобода ≥ p75 и чистота ≥ p50.
2. В карточке ниши проверяет, из чего сложилась свобода, какие ключи свободны, кто зашёл без закупки, в каком гео вход дешевле и сколько это денег.
3. Переходит в «Топ приложений» с фильтром по нише, при необходимости включает «Скрыть выросших на покупном трафике».
4. В карточке приложения смотрит семь проверок, историю рекламы, источник трафика и прикидывает окупаемость по ёмкости ниши.

## 3. Разбор методики v2.0

### 3.1. Что принято без изменений

Разделение ниши на свободу и органический потенциал; свободные ключи вместо медианного door; курс «спрос → установки» и ёмкость в установках в месяц; чистота органики, взвешенная по спросу; проверка 3b; срок годности отрицательной улики; историческая закупка; матрица решения; порог окупаемости при нулевой закупке; бэктест как критерий приёмки скора.

### 3.2. Поправки

| № | В методике | Проблема | Как в ТЗ |
|---|---|---|---|
| П1 | `k_geo = median(installs_growth_30d / weight)`; то же в `aso_share` | `installs_growth_30d` в базе — относительный рост (доля), а не установки; и он пуст у приложений меньше 50K установок — ровно у молодых новичков | Новое поле `installs_delta_30d` — абсолютный прирост установок за окно, приведённый к 30 дням, без нижней границы (5.8) |
| П2 | 3b: пройдена при `aso_share ≥ p50` ниши, провалена при `< p25` ниши | Курс калибруется на тех же органиках, а `aso_share` обрезается до 1: у половины выборки значение ровно 1, p50 = 1, и «пройдена» означает «поиск объясняет весь рост». Квантили ниши к тому же считаются по единицам приложений | Провалена — `aso_share < p25` гео; пройдена — иначе при непустом значении; пусто — не проверена (5.9) |
| П3 | Срок годности улики 30 дней | K7 (проверка рекламных библиотек Google Ads Transparency / Meta Ad Library) не переспрашивает проверенный домен: через месяц почти все «не найдено» протухнут | Срок годности вводится сейчас; перепроверка раз в 30 дней — отдельная задача сбора (10). Отчёт показывает, сколько улик протухнет в ближайшие 7 дней |
| П4 | `ads_first_seen`, `ads_last_seen`, `ads_ever_found` из дат обеих библиотек | Даты не сохранялись ни для одной библиотеки. Meta вне ЕС показывает только активные объявления | Google: даты первого и последнего показа уже лежат в сыром ответе (`raw_ads_google_field`, пути `1.N.6.1` и `1.N.7.1`, секунды; у всех 28 339 объявлений первый показ ≤ последнего, диапазон 07.2019–09.2026) — считаются без нового сбора. Meta: только «найдено когда-либо в наших проверках»; даты — отдельная задача сбора |
| П5 | «Возраст > 18 мес и `ads_ever_found = 1` → рост не был органическим» | Дублирует таблицу ступеней: `ads_ever_found = 1` уже даёт «Закупка найдена» при любом возрасте | Правило не вводится отдельно |
| П6 | `time_to_door_median` — возраст на момент достижения door | Истории установок с релиза нет | Оценка по средней скорости: `door / installs_per_month_lifetime`, не больше возраста; помечается «оценка» |
| П7 | `time_to_organic` до 90 снимков — по вошедшим при нас | При недельной истории вошедших при нас нет, поле пусто везде | Два вида значения: «измерено» — по вошедшим при нас; «не позже» — медианный возраст молодых органиков на дату первого снимка, где они уже в топ-10 |
| П8 | `niche_rank = freedom_pct × organic_purity × log10(1 + organic_capacity)` | Ёмкость пуста, пока нет курса (истории) — сортировать нечем | Основа ранга выбирается на гео: «полная», если курс гео посчитан; иначе «без ёмкости» — `freedom_pct × organic_purity`. Ранги сравниваются между гео только процентилями (7.2) |
| П9 | `norm(demand_per_app)` линейно по p10–p90 | Величина в установках с тяжёлым хвостом: линейная нормировка сжимает всё, кроме хвоста | Нормировка по `log10`, как у `demand` в prescore |
| П10 | Разбор таблицы «`free_keys_count ≥ 8`» | Абсолютный порог | p75 `free_keys_count` по нишам гео |
| П11 | Служебные числа: 30 наблюдений курса, 60 % покрытия чистоты, 30 дней улики, позиция 5 ёмкости, ≥ 3 приложения разработчика в нише | Это не пороги значений, а условия полноты, окна и формы | Выносятся в `config/scoring.json`, раздел `v2`, с пометкой «служебные»; критерий приёмки 7 их не считает нарушением |
| П12 | `young_organic_count`: < 18 мес (3.4); 12 мес (6.1) | Противоречие внутри методики | 12 мес (решение 2) |
| П13 | Возраст известен у 53 % строк (P3, п. 20: «отдельная работа») | Даты релиза записаны на языке карточки: «14 janv. 2018», «20.04.2015», «2017. 9. 7.», «10 ביולי 2023». Разбирался только английский формат | Разбор дат на 21 языке карточек словарём месяцев (5.11) — без нового сбора. Цель ≥ 95 % |
| П14 | `turnover_up_new`, `entry_rate_90d` на коротком окне | Позиция 11 → 10 выглядит как «вход» — шум | Считаются при окне ≥ 14 дней; до 90 (для `entry_rate_90d`) и до 30 (для `turnover_up_new`) — с пометкой `partial_window` |
| П15 | Чистота: ключ «закуплен», если в топ-10 кто-то закупает | На данных US у 41 из 43 ниш чистота получилась ровно 0: закупка или трекер найдены у половины приложений, и в топ-10 почти любого ключа есть хотя бы одно такое. Матрица вырождалась | Доля трафика ключа, уходящая закупающим: места топ-10 взвешиваются кривой CTR (5.3, 5.6). Это прямо следует из мысли методики «один закупленный лидер весит больше пяти чистых на хвосте». После поправки распределение чистоты непрерывное, все четыре квадранта заполнены |
| П16 | «Реклама проверена» для покрытия чистоты | Ступень «признаков закупки нет» требует скана трекера, которого у приложений вне реестра нет, — покрытие занижалось | Реклама проверена: ступень `found` или обе библиотеки пусты со свежей уликой; скан трекера для покрытия не нужен |
| П17 | Проверка 2: «в верхней трети гео» | У большинства ниш `index_gap_leader` = 0, граница верхней трети = 0, и признак выполнялся у всех | Признак выполняется при значении ≥ границы **и** больше нуля |
| П18 | `time_to_organic` «измерено» | При недельной истории «входы» — перетасовка позиций | «Измерено» — только при окне ≥ 14 дней, иначе «не позже» |
| П19 | Ниша из 1–2 ключей (остаток концепта) | Доля свободного спроса там 0 или 1 — индекс свободы шумный | Ранг считается, ниша помечается «неполные данные: узкое ядро» и исключается фильтром «Только полные данные» |
| П20 | УБТ-сигнал — `exogenous_spike_rate` (всплески установок без роста в поиске) | Нужны 20 дневных точек — до ≈ 07.10 пусто; всплеск не говорит, откуда пришли люди | Добавлен прямой косвенный признак — упоминания площадок в отзывах (5.13). `exogenous_spike_rate` остаётся в карточке |
| П21 | Отзывы — на языках гео | Отзыв хранится один раз, под языком первого гео, где собиралось приложение: у поздних гео своих отзывов почти нет (IT — у 12 приложений из 255) | УБТ считается по отзывам приложения на всех собранных языках; порог — p75 внутри гео |

### 3.3. Что зависит от истории

История выдачи и карточек началась 7 сентября 2026; самая длинная на 15.09 — 8 дней, у части гео — один снимок. Поля ниже код считает сам, как только окно накопится; до этого они пусты с подписью «копится: N из M дней».

| Величина | Нужно | Включится не раньше |
|---|---|---|
| `installs_delta_30d`, курс `k_geo`, ёмкость, проверка 3b, `door_velocity` | Окно ≥ 14 дней (до 30 — с пометкой) | 21.09 для гео с первым снимком 07.09 |
| `turnover_up_new` | 14 дней (полное — 30) | 21.09 / 07.10 |
| `entry_rate_90d`, `last_entry_days` | 14 дней (полное — 90) | 21.09 / 06.12 |
| Флаг «ниша закрыта» (`last_entry_days > p90`) | 90 дней | 06.12 |
| `exogenous_spike_rate` | 20 дневных точек за 30 дней | ≈ 07.10 при ежедневном сборе гео |
| Тренд свободы за 30 дней | 30 дней метрик ниш | 07.10 |
| Бэктест (приёмка 15) | 90 дней | 06.12 |

«Не раньше» — если гео снимается ежедневно. Фактическая дата гео видна на странице «Сбор и планы».

## 5. Расчётный слой

### 5.1. Где хранится

Новые величины пишутся в **отдельные таблицы**. Стадии `niche-doors` и `score` перезаписывают строки `metrics_niche_geo` и `metrics_app_geo` целиком (`INSERT OR REPLACE` с явным списком колонок), и новые колонки там обнулялись бы при каждом пересчёте.

| Таблица | Ключ | Содержимое |
|---|---|---|
| `metrics_keyword_geo` | geo, keyword, snapshot_date | Ключ ядра: ниша, спрос, `door_key`, свободен ли, есть ли закупка в топ-10, покрытие проверки рекламы |
| `metrics_niche_v2` | niche_id, geo, snapshot_date | Метрики свободы, компоненты и индекс свободы, курс гео, ёмкость, чистота, молодые органики, срок, ранг, квадрант, списки пустых полей |

Квантили, на которые опираются нормировки и пороги этих таблиц, пишутся в `niche_quantiles` (scope `geo`, scope_id `<гео>:v2`).

### 5.2. Новая стадия и её место

Стадия `radar-v2` идёт после третьего `score` в планах DISCOVERY и DAILY и перед отчётами. Дата — дата прогона; при ручном пересчёте — последний день гео с метриками (`latestShownDate`). Сырьё не трогается; строки дня пересчитываются целиком.

Выдача берётся на дату или раньше (последний снимок ключа ≤ даты), карточки — последняя в гео на дату или раньше.

### 5.3. Ключи ядра

Для каждого небрендового ключа ядра ниши:

| Поле | Определение |
|---|---|
| `suggest_score` | Из `disc_keywords` |
| `door_key` | Минимум установок в сыром топ-10 ключа; как в `niche-doors`: не меньше 3 карточек, строки «оценок больше, чем установок» исключены |
| `is_free` | `door_key ≤ p25 door_key` по всем ключам гео **и** `suggest_score > 0` **и** `suggest_score ≥ p50` по ключам ниши |
| `paid_in_top10` | В топ-10 есть приложение со ступенью «Закупка найдена» (описательное) |
| `paid_ctr_share` | Σ ctr(место) закупающих / Σ ctr(место) приложений с проверенной рекламой, по топ-10 (П15) |
| `ads_checked_share` | Σ ctr(место) приложений с проверенной рекламой / Σ ctr(место) всего топ-10. Реклама проверена — ступень `found` или обе библиотеки пусты со свежей уликой (П16) |

### 5.4. Свобода

**Метрики:**

| Поле | Определение | Пусто, если |
|---|---|---|
| `free_keys_count` | Число свободных ключей ядра | `door_key` есть меньше чем у половины ключей ядра |
| `free_demand_share` | Σ спроса свободных ключей / Σ спроса ядра | то же, или Σ спроса ядра = 0 |
| `door_head`, `door_tail` | Медиана `door_key` по верхней четверти ключей по спросу / по остальным | ключей ядра < 4 |
| `door_velocity` | Медиана по ключам ядра от `installs_delta_30d` приложения с `door_key` | окно < 14 дней |
| `demand_per_app` | `demand_installs / apps_count` | — |
| `aso_saturation` | Доля топ-10 головного ключа с точным вхождением всех токенов ключа в заголовок | карточек меньше 5 из 10 |
| `entry_rate_90d` | Приложений, впервые вошедших в топ-10 любого ключа ядра за окно (≤ 90 дней): в топ-10 на снимке, и ни на одном более раннем снимке этого ключа в окне в топ-10 не было | окно < 14 дней |
| `last_entry_days` | Дней с последнего такого входа; нет входов — пусто с подписью «> N дней» | окно < 14 дней |
| `time_to_door_median` | Медиана по топ-10 головного ключа от `min(door / installs_per_month_lifetime, age_months)`, оценка | возраст известен меньше чем у половины |
| `turnover_up_new` | Σ по ключам ядра приложений в топ-10 сегодня, которых на снимке окна не было в топ-50 / Σ приложений в топ-10 сегодня, которых на снимке окна не было в топ-10; нет оборота — 0 | окно < 14 дней |
| `hhi_top10` | Σ (доля установок i-го в топ-10 головного ключа)²; описательное | стены нет |
| `clone_density` | Доля объединённого топ-50 ядра от разработчиков, у которых в этом топ-50 ≥ 3 приложения или `is_factory = 1` | разработчик известен меньше чем у половины |

**Индекс:**

```
freedom_raw = Σ wᵢ·nᵢ / Σ wᵢ   (по непустым компонентам)

n₁ = free_demand_share                         w = 0,25
n₂ = norm(relevance_gap_pct)                   w = 0,15
n₃ = 1 − norm(aso_saturation)                  w = 0,15
n₄ = norm(log10(1 + demand_per_app))           w = 0,15
n₅ = norm(entry_rate_90d)                      w = 0,15
n₆ = norm(turnover_up_new)                     w = 0,10
n₇ = 1 − norm(clone_density)                   w = 0,05

norm(x) = clip((x − p10) / (p90 − p10), 0, 1) по нишам гео
freedom_pct = процентиль freedom_raw среди ниш гео (0–100)
```

- Пустая компонента исключается вместе с весом; ниша получает бейдж «неполные данные» со списком.
- Если сумма весов непустых компонент меньше `freedom_min_weight` (0,5), индекс пуст.
- В базу пишутся все `nᵢ` и вклад каждой — карточка воспроизводит значение.
- Флаг «ниша закрыта»: `last_entry_days > p90` гео, только при окне ≥ 90 дней. Скор показывается, строка не скрывается.

### 5.5. Курс «спрос → установки» и ёмкость

**Кривая CTR** — форма из `config/scoring.json`: 1,00 / 0,55 / 0,38 / 0,28 / 0,22 / 0,18 / 0,15 / 0,13 / 0,11 / 0,10 для мест 1–10; 0,05 для 11–20; 0,02 для 21–50. Помечена «приор, калибруется».

**Вес приложения:** `weight(app) = Σ по небрендовым ключам ядер всех ниш гео, где app в топ-50: suggest_score × ctr(место)`.

**Выборка калибровки:** приложения гео в топ-10 хотя бы одного ключа ядра; ступень органики «подтверждена» или «признаков закупки нет»; возраст известен; `installs_consistency = 1`; `installs_delta_30d > 0`; `weight > 0`.

```
k_geo = median(installs_delta_30d / weight)       // p25, p75 — интервал
```

Меньше 30 наблюдений (`calibration_min_obs`) или окно < 14 дней — курс пуст, статус с причиной.

**Ёмкость:**

```
organic_capacity    = k_geo × Σ_{свободные ключи} suggest_score × ctr(5)    // установок в месяц
organic_capacity_lo = k_p25 × …;  organic_capacity_hi = k_p75 × …
money_capacity      = organic_capacity × money_ratio                        // в «установках US»
```

Нет свободных ключей при посчитанном `free_keys_count` — ёмкость 0 (измерено). Пустой `free_keys_count` — ёмкость пуста.

### 5.6. Чистота органики

```
organic_purity = 1 − Σ_{ключи ядра} suggest_score × paid_ctr_share / Σ_{ключи ядра с проверкой} suggest_score
```

- Взвешивание двойное: по спросу ключа и по месту в его топ-10 (П15).
- Если Σ спроса ядра = 0, ключи берутся с равными весами.
- Пусто, если покрытие `Σ suggest_score × ads_checked_share / Σ suggest_score` меньше 0,6 (`purity_min_checked_share`).
- Описательно рядом: `top10_ads_share` — доля приложений топ-10 головного ключа с закупкой.

### 5.7. Доказанный вход, срок, ранг, матрица

| Поле | Определение |
|---|---|
| `young_organic_count` | Приложения объединённого топ-20 ядра: возраст < 12 мес, ступень «признаков закупки нет» или «подтверждена». Пусто, если возраст известен меньше чем у половины |
| `young_organic_installs` | Сумма их установок |
| `time_to_organic`, `time_to_organic_kind` | П7, П18: «measured» — медиана возраста на дату входа по вошедшим при нас, только при окне ≥ 14 дней; иначе «upper» — медиана возраста на первый снимок, где они в топ-10 |
| `candidates_count` / `candidates_organic_count` / `candidates_paid_count` | Приложения ниши, прошедшие воронку в гео: всего / без найденной закупки / с закупкой |
| `monetized_share` | Доля топ-10 головного ключа с `monetization_proof = 1`; пусто, если карточек меньше 5 |

| `niche_rank`, `rank_basis` | П8: `full` — `freedom_pct × purity × log10(1 + capacity)`; `no_capacity` — `freedom_pct × purity`. Пустая чистота заменяется медианой гео с бейджем «неполные данные»; пустая свобода — ранга нет |

### 5.8. Приложение: органика, история рекламы, источник трафика

**Улика отсутствия рекламы** — дата самой старой из двух последних успешных проверок: Google (домен приложения, как в K7: сайт, иначе хост privacy policy) и Meta (детектор v2). `evidence_age_days = дата − дата улики`.

**История рекламы:**

| Поле | Определение |
|---|---|
| `ads_google_first_seen`, `ads_google_last_seen` | Минимум первого и максимум последнего показа по объявлениям домена в последнем успешном ответе Google |
| `ads_google_creatives` | Число объявлений в ответе |
| `ads_google_active` | Последний показ не старше 30 дней от даты проверки |
| `ads_meta_ever` | Meta нашла объявление со ссылкой на карточку хотя бы в одной нашей проверке |
| `ads_ever_found` | Любое из двух |

**Ступени органики:**

| Ступень | Условие | Проверка 3 |
|---|---|---|
| `found` — Закупка найдена | `ads_found ∈ {google, meta, both}`, или `attribution_sdk = 1`, или `ads_ever_found = 1` | провалена |
| `confirmed` — Органика подтверждена | Обе библиотеки пусты, APK разобран без SDK атрибуции, улике ≤ 30 дней | пройдена |
| `no_signs` — Признаков закупки нет | Обе библиотеки пусты, скан текста трекер не нашёл, APK не разобран, улике ≤ 30 дней | не проверена |
| `stale` — Улика протухла | Было бы `confirmed` или `no_signs`, но улике > 30 дней | не проверена |
| `unchecked` — Не проверено | Иначе | не проверена |

**Прирост установок:** `installs_delta_30d = (installs(дата) − installs(дата − w)) × 30 / w`, где w — расстояние до самого старого снимка карточки в пределах 30 дней, не меньше 14; при w < 30 — `delta_partial = 1`. Источник установок не должен меняться внутри окна (как в `score`).

**Источник трафика:**

```
explained = k_geo × weight(app)
aso_share = clip(explained / installs_delta_30d, 0, 1)
```

Пусто, если нет курса, прироста или прирост ≤ 0. `traffic_source`: `external` — `aso_share < p25` гео; `search` — иначе при непустом значении.

**Всплески:** `exogenous_spike_rate` — доля дней за 30, где дневной прирост выше p95 собственных дневных приростов приложения, при неизменных `title_hash`, `short_desc_hash`, `listing_hash` и без найденной рекламы. Считается при ≥ 20 дневных точках.

### 5.9. Семь проверок

Хранятся в `metrics_app_v2.checks` (массив из семи значений 1 / 0 / пусто), `passed`, `failed`, `unknown`.

| № | Проверка | Пройдена | Провалена | Иначе |
|---|---|---|---|---|
| 1 | Спрос органический | `demand ≥ 0,5` и `src_ads_pct ≤ p95` ниши (оба известны) | `demand < 0,25` или `src_ads_pct > p95` ниши | не проверена |
| 2 | Инкумбент побеждаем | Любое: `weak_share` ниши в верхней трети ниш гео и больше нуля; `index_gap_leader` в верхней трети и больше нуля (П17); лидер головного ключа не обновлялся дольше p90 гео | Все три известны, ни одно не выполнено | не проверена |
| 3 | Вырос без закупки | Ступень `confirmed` | Ступень `found` | не проверена |
| 3b | Трафик поисковый | `traffic_source = search` | `traffic_source = external` | не проверена; при ступени `found` или `unchecked` — не проверена |
| 4 | Дёшев в повторении | `feasibility ≥ 0,75` | `feasibility ≤ 0,25` | не проверена |
| 5 | Монетизация доказана | `monetization_proof = 1` | `monetization_proof < 1` | не проверена |
| 6 | Переживёт модерацию | `policy_ok = 1` | `policy_ok = 0` и `policy_auto_ok = 0` | не проверена |

`demand` и `feasibility` — нормированные доли шкалы (ТЗ v2.1, 9.4), а не абсолютные пороги.

### 5.10. Дисквалификаторы

Приложения, отсеянные воронкой (`factory`, `branded_only`, `too_big`, `low_monetization`, `fraud_extreme`, политики, бюджетная локализация, `heavy_and_bad`), в отчёт не попадают. Среди прошедших воронку `metrics_app_v2.disq` отмечает:

| Код | Правило | По умолчанию |
|---|---|---|
| `paid` | Ступень `found` | Видно; скрывается галочкой «Скрыть выросших на покупном трафике» |
| `external` | `traffic_source = external` | Видно, бейдж |
| `fraud` | `fraud_ok = 0` | Скрыто, «Показать отсеянных» |
| `wall` | `wall_installs` или `wall_ratings` ниши выше p90 гео | Скрыто, «Показать отсеянных» |

### 5.13. УБТ по отзывам

**УБТ** — условно-бесплатный трафик: приложение узнают из соцсетей и видео (TikTok, YouTube/Shorts, Instagram/Reels, блогеры), а не из поиска Play и не из рекламы.

**Разметка — стадия `analyze-ubt`** (после `analyze-pain` во всех планах). Словарь `config/ubt-lexicon.json`, версия `ubt-v2`, 18 языков. Метки в `review_labels`:

| Метка | Что ищется | Пример |
|---|---|---|
| `ubt_platform` | Название площадки или роль: TikTok, YouTube, YouTube Shorts, Instagram, Reels, ютубер, тиктокер, блогер, инфлюенсер | «как у блогера в видео» |
| `ubt_phrase` | Фраза-источник: площадка как место, где узнали | «увидел в тиктоке», «found it on YouTube», «came from TikTok» |

Разметка общая для всех гео; прогресс — водяной знак по `rowid` в `label_progress`, повторный запуск берёт только новые отзывы. Смена версии словаря размечает всё заново.

**Приложение** (`metrics_app_v2`):

| Поле | Определение |
|---|---|
| `ubt_reviews` | Собранных отзывов приложения на всех языках (П21) |
| `ubt_related` | 1, если площадка в названии или кратком описании, жанр из `platform_related_genres` (фото, видео, соцсети, связь, музыка, развлечения) или концепт ниши из `platform_related_concepts` |
| `ubt_mentions` | Отзывов с меткой: при `ubt_related = 1` — только `ubt_phrase`, иначе любой (П22) |
| `ubt_share` | `ubt_mentions / ubt_reviews` при `ubt_reviews ≥ 20`, иначе пусто |
| `ubt_signal` | 1 — `ubt_mentions ≥ 3` и `ubt_share ≥ p75` гео среди приложений с долей > 0 (П23); 0 — доля посчитана, но ниже; пусто — мало отзывов |

**Ниша** (`metrics_niche_v2`): `ubt_apps` — приложений топ-20 ключей ядра и кандидатов с посчитанным признаком; `ubt_share` — доля с `ubt_signal = 1` среди них при `ubt_apps ≥ 3`; `ubt_flag` — 1 при `ubt_share > 0` и `≥ p75` ниш гео.

**Канал роста** (фильтр, 7.5 и 8.3):

| Канал | Приложение | Ниша |
|---|---|---|
| Органика (поиск) | Ступень «Признаков закупки нет» или «Подтверждена», `ubt_signal ≠ 1` | Чистота ≥ p50 гео, `ubt_flag ≠ 1` |
| Органика + УБТ | Та же ступень и `ubt_signal = 1` | Чистота ≥ p50 гео и `ubt_flag = 1` |
| УБТ | `ubt_signal = 1` при любой ступени, в том числе с закупкой (решение 7a) | `ubt_flag = 1` |
| Закупка найдена | Ступень `found` | — |
| Не проверено | Ступени «Не проверено» и «Улика протухла» | — |

Признак косвенный: упоминание не доказывает, что трафик пришёл из видео, и отсутствие упоминаний не доказывает обратного. Это ориентир для ручной проверки — поиска роликов о приложении.

### 5.14. Рекомендуемый скор

Взвешенная сумма частей 0–1; пустая часть исключается вместе с весом. Процентиль `rec_pct` — внутри гео. Веса — `config/scoring.json`, `v2.recommended`; это гипотеза, не валидирована бэктестом.

**Приложение** — только прошедшие воронку; закупка (`found`), накрутка и стена авторитета не рекомендуются. Нормировки — по прошедшим воронку в гео.

| Часть | Вес | Из чего |
|---|---|---|
| Рост из поиска (ASO) | 35 % | Процентиль веса в выдаче гео (50 %); ключей в топ-10, p10–p90 (30 %); источник трафика: поиск = 1, внешний = 0 (20 %) |
| Свобода ниши | 25 % | Доля свободного спроса (60 %); индекс свободы / 100 (40 %) |
| Пройденные проверки | 15 % | Пройдено из 7 / 7 |
| Индекс копируемости | 10 % | prescore / 100 |
| Молодость и прирост | 10 % | 1 − возраст, p10–p90 (60 %); процентиль прироста за 30 дней (40 %) |
| Монетизация | 5 % | `monetization_proof` |

Итог умножается на ступень органики: «признаков нет» и «подтверждена» × 1; «улика протухла» × 0,8; «не проверено» × 0,6.

**Ниша** — квадрант «Мимо» и закрытые ниши не рекомендуются.

| Часть | Вес | Из чего |
|---|---|---|
| Свободные ключи | 40 % | Доля свободного спроса (70 %); процентиль `free_keys_count` (30 %) |
| Остальная свобода | 15 % | Индекс свободы / 100 |
| Чистота | 20 % | `organic_purity` |
| Молодые органики | 10 % | Процентиль числа молодых органиков |
| Монетизация у топа | 10 % | `monetized_share` |
| Ёмкость | 5 % | Процентиль ёмкости; пока курса нет — процентиль суммарного спроса |

**Рекомендуемый топ** — первые `top_n` = 50 по `rec_pct` после остальных фильтров. В ворлдвайд строка берётся из гео с лучшим рекомендуемым скором (П24). Рекомендуемые приложения (первые 150 гео) попадают в отчёт, даже если по индексу копируемости они ниже отсечки 500 строк.

### 5.16. Предварительный прирост и перенос строк

**Предварительный прирост** (`metrics_app_v2`): `delta_preview` — разница установок между самым ранним и последним снимком за 30 дней, приведённая к 30 дням; `delta_preview_raw` — та же разница в установках, `delta_preview_w` — длина окна в днях, `delta_preview_from` — дата раннего снимка. Ряд собирается по карточкам всех гео: установки у приложения общие для Play (в один день совпадают у 96 % приложений), поэтому окно получается длиннее, чем по истории одного гео. Минимальная длина окна — `preview_min_window_days` (1 день). Строки «оценок больше, чем установок» отбрасываются как артефакт Play.

Поле только для просмотра: в курс гео, `aso_share`, проверку 3b и рекомендуемый скор входит официальный `installs_delta_30d` с окном ≥ 14 дней. В отчёте показывается, когда официального нет: «≈ +N, предв., W дн.», в подсказке — исходная разница, дата раннего снимка и предупреждение о шуме коротких окон.

**Перенос строк.** Отчёт берёт для приложения последнюю строку не старше `report_carry_days` (7 дней), а не строго последний день гео (П27). Если строка старше дня гео, рядом с названием и в карточке стоит «данные на дд.мм». Ниши и квантили — всегда за последний день гео.

## 6. Общий интерфейс

### 6.1. Оформление и навигация

Оформление AppRadar (как в опубликованном отчёте): тёмное меню слева, светлое поле с карточками, Manrope и JetBrains Mono, светлая и тёмная темы. AppRadar v1 остаётся; этот отчёт — отдельный артефакт **«AppRadar 2»**.

Разделы меню: **Топ приложений**, **Топ ниш**, **Избранное**, **Сбор и планы**.

Шапка: поиск; выбор «Ворлдвайд / 30 гео» с числом строк; дата данных; переключатель темы.

### 6.2. Правила отображения

- Пустое — «—» с причиной: «копится: N из M дней», «не проверено», «нет курса гео», «мало карточек».
- Порог подписан значением: «чистота ≥ p50 гео = 0,72».
- Четыре числа ниши везде показываются вместе и в одном порядке: Свобода · Ёмкость · Чистота · Срок.
- Оценки (ёмкость, `time_to_door_median`, `time_to_organic` «не позже») помечены «≈».
- Бейджи содержат текст; цвет не единственный носитель смысла.

### 6.3. Производительность и публикация

Один HTML, данные встроены и упакованы колонками, ≤ 16 МБ (до 500 строк приложений на гео плюс рекомендуемые, 5.14). Первая отрисовка ≤ 2 с, фильтр ≤ 300 мс на 10 000 строк. Избранное, тема, галочки и ввод калькулятора — в `localStorage` с безопасной обработкой. Отчёт пересобирается стадией `appradar2` после `radar-v2`; публикуется раз в сутки после прохода всех гео и по команде.

### 6.4. Подсказки

У каждого варианта фильтра, заголовка колонки, карточки сводки, бейджа и строки карточки — всплывающая подсказка. Своя, не `title` браузера: у вариантов выпадающих списков стандартная не показывается, а объяснение из трёх частей в неё не помещается.

| Часть | Содержимое |
|---|---|
| Что это | Термин простыми словами |
| Как считается | Формула или правило с порогом и его значением в гео |
| Зачем | Какое решение помогает принять |

Открывается наведением и фокусом с клавиатуры, у значка «?» — нажатием; закрывается уходом курсора, прокруткой, Escape. У выпадающих списков значок «?» рядом объясняет все варианты. Тексты — словарь `GLOSS` в шаблоне; веса и пороги подставляются из конфигурации.

| Ключи | Ключи, где приложение в топ-50: место, спрос, ctr, вклад в вес |
| Ниша | Четыре числа, квадрант, переход к карточке ниши |
| Деньги и окупаемость | Монетизация, iap, `installs_per_month_lifetime`; калькулятор: ввод конверсии, ARPU подписки, стоимости разработки и поддержки в месяц → `доход/мес = ёмкость ниши × conv × ARPU × money_ratio` и срок окупаемости; ёмкость и лидерская скорость подставлены как верхняя граница |
| Присутствие по гео | Гео, прошло воронку, prescore, ступень, квадрант ниши |
| Что проверить вручную | policy_ok (E7), разбор APK (установочного файла приложения), показываемость за 3 секунды |

## 9. «Сбор и планы»

Как в AppRadar v1, плюс блок **«Готовность методики v2»**: для каждой величины из 3.3 — сколько гео уже имеют окно, дата включения по каждому гео, число улик, которые протухнут в ближайшие 7 дней, покрытие возраста, door, проверки рекламы и калибровки.

## 10. Вне объёма

- **Сбор:** даты объявлений Meta; перепроверка рекламы раз в 30 дней; добор карточек топ-10 ключей ядра; очередь проверки рекламы для топ-10 ключей ядра. Отчёт показывает их нехватку, но не закрывает её.
- **Корзина ключей кандидата** (методика, P3, п. 17) и персональная свобода.
- **Переоценка кривой CTR** по собственным данным (P3, п. 19) — после 30 дней истории.
- **Бэктест** — код критерия 15 после 90 дней.
- **Сбор УБТ с площадок** (поиск роликов в Shorts, TikTok, Reels) — УБТ в этой версии только по отзывам (5.13); ручная метка показываемости.
- Валидация весов рекомендуемого скора — вместе с бэктестом после 90 дней.
- Выручка, конверсия, удержание — только ручной ввод в калькулятор.

## 11. Приёмка

| № | Критерий | Как проверяется |
|---|---|---|
| 1 | Четыре раздела в оформлении AppRadar, обе темы, поиск, «Ворлдвайд / гео» | Просмотр |
| 2 | В «Ворлдвайд» каждое приложение и каждый концепт — одна строка | Сверка с уникальными id |

| 4 | Ни одна проверка не пройдена при пустых входах; проверка 3 не пройдена без APK; 3b не пройдена при пустом `aso_share` | SQL по всем строкам |
| 5 | Ступень `found` у всех с `ads_found ∈ {google, meta, both}`, `attribution_sdk = 1` или `ads_ever_found = 1`; улика старше 30 дней даёт `stale` | SQL |
| 6 | `freedom_raw` воспроизводится из компонент карточки с точностью до округления | Сверка 10 ниш |
| 7 | Пороги значений — только квантили; абсолютных два разрешённых; служебные числа лежат в `config/scoring.json`, раздел `v2` | Просмотр конфигурации и кода |

| 9 | Страница ≤ 16 МБ; отрисовка ≤ 2 с; фильтр ≤ 300 мс | Замер |
| 10 | Галочка скрывает ровно ступень `found`, счётчик совпадает с числом таких строк в выборке | Просмотр и сверка |
| 11 | Молодые органики — возраст < 12 мес и ступень `no_signs` или `confirmed` | SQL |
| 12 | Курс гео пуст при выборке < 30 или окне < 14 дней; ёмкость в таком гео пуста, основа ранга `no_capacity` | SQL по `metrics_geo_calibration` |
| 13 | Возраст известен у ≥ 95 % строк, прошедших воронку | SQL |

| 15 | Бэктест: precision@15 свободы выше сортировки по `demand_installs` | После 90 дней истории |
